// Darwinbox · product case study

Custom Objects: flexible data modelling, in progress.

I am the only PM on this. I define the use case, scope the product, and onboard clients myself.

In progress · Use-case definition, before client onboarding
01 — Problem

Configuration limits to define.

Customers need to track business-specific records that do not fit Darwinbox’s standard modules, so they fall back on spreadsheets or custom development. Working assumption.

02 — Who it’s for

The customer admin’s job.

Customer type/persona: HR or operations admin at a mid-to-large enterprise Darwinbox customer. Working assumption.

Job to be done: Model and track a business-specific record linked to employees inside Darwinbox, without engineering help. Working assumption.

03 — First use case

Choose one place to start.

First use case: Asset and equipment allocation tracking linked to employee records. Working assumption.

Deprioritized: Cross-object reporting, approval workflows, external API exposure, and advanced permission models. Working assumption.

04 — Scope & key decisions

Define the MVP before expanding.

MVP in scope

Create a custom object, define fields, link records to employees, create/edit/search records, and support role-based access. Working assumption.

→
Deferred

Formulas and rollups, multi-object relationships, workflow automation, and analytics dashboards. Working assumption.

→
Trade-off

Ship a narrow, opinionated object builder for one use case to reach a real client fast instead of a fully generic platform. Working assumption.

05 — Client onboarding approach

Start with the right first clients.

Pick 1–2 existing clients with a clear manual workaround, co-define the use case in discovery calls, configure the first object with them, and review feedback weekly. Working assumption.

Measure time to first object, records created in the first two weeks, repeat admin usage, and support requests needed. Working assumption.

06 — Success metrics

Planned measures, not results.

AdoptionWeekly active admins at both pilot clients within the first month
Time to first objectUnder 1 hour from onboarding call to first live object
Client onboarding2 pilot clients in the first phase; 5 by the end of the next quarter
07 — What I’m learning / next steps

Build from client evidence.

I am using the first use case and client onboarding to validate the MVP. Next, I will use what I learn to decide whether to expand scope.
